# 索尼创意外观（Creative Look）渲染流程与算法

来源：Sony Imaging Edge Desktop **Edit 4.1.00**（macOS，x86_64 切片），全部结论来自对 Edit 机器码的反汇编与执行（先用 Unicorn 模拟，后在 Linux x86_64 上原生执行），以及 ARW 文件中的实际数据；**没有拟合参数**。

配套参数文件：[`creative_look_params.json`](creative_look_params.json)（ILCE-7CM2 / ILCE-7M5 每个外观的全部参数）。

---

## 1. 结论速览

- 每个创意外观的参数**写在 RAW 文件里**（加密的 SR2SubIFD），每个外观一个 IFD。Edit 不内置外观色彩数据。
- 外观之间真正不同的只有 **9 个标签**：`0x7800 0x7806 0x780c 0x780d 0x780e 0x780f 0x7842 0x7844 0x7845`。其余 100 多个标签对所有外观完全相同。
- 外观的“滑块”部分（对比度、高光、阴影、褪色、饱和度、锐度、锐度范围、清晰度）来自 Edit 内置的预设表；FL2/FL3 不在表中，沿用相机 MakerNote 中的设置。
- 一个外观的完整渲染 = 共享的 RAW 处理 + 外观专属的 **逐色相矩阵（LM16）→ 主伽马 → 色度系数 → 亮度伽马/褪色 → 清晰度 → 黑白/褐色效果**。
- 用 Edit 自己的代码（原生运行）从 RAW 渲染 A7M5 全部 12 个外观，与 Edit 导出相比 16px 块 RMSE **0.003–0.006**（VV2 为 0.011），逐亮度段无系统偏差。

## 2. 数据在 ARW 中的位置

| 位置 | 内容 |
|---|---|
| `SR2Private` → `SR2SubIFD` | 加密（dcraw `sony_decrypt`，密钥来自 `0x7221`）。包含全局渲染参数。 |
| `SR2SubIFD` 标签 `0x74c0` | N 个偏移，各指向一个 `SR2DataIFD`，即一个外观（A7C II：10 个；A7M5：12 个，含 FL2/FL3）。 |
| `SR2DataIFD` 标签 `0x7770` | 外观名（Standard/Vivid/Neutral/Portrait/FL/VV2/IN/SH/BW/Sepia/FL2/FL3）。 |
| MakerNote `0x2004–0x2036` | 相机当时的外观滑块（对比度、高光、阴影、褪色、锐度、锐度范围、清晰度、饱和度），由 `0x1000a62c0` 解析到 ZcARW+0x19c。 |
| MakerNote `0xb025` | DynamicRangeOptimizer，决定是否启用 DRO 任务（Vatr）。 |
| IFD0 `0xb000` | FileFormat → 内部版本号：4.x→0x34xx，6.x→0x3600（`0x1000a5fd0`）。 |
| MakerNote `0xb001` | 机型 ID（A7C II=397，A7M5=407），影响褐色效果参数的选择。 |

外观 IDF 的读取：`0x1000a9fd0` 为每个外观建立参数集（0x1328 字节），先用 `0x1000a6990` 读共享标签，再用 `0x1000aafa0` 读外观标签。`ZcARW::vfunc+0xe0` 按色彩模式 ID 返回对应参数集。

色彩模式 ID：`2 ST, 4 VV, 7 NT, 8 PT, 16 BW, 17 SE, 18 FL, 19 VV2, 20 IN, 21 SH, 22 FL2, 23 FL3`。

## 3. 设置（settings）如何形成

1. `0x1000b2710`（构造）→ `0x1000b25f0`（复位）。
2. `0x1000aa870`：从 RAW 带入拍摄时的设置（DRO 来自 `0xb025`，镜头畸变/色差校正模式，白平衡模式等）。
3. 切换外观：预设函数 `0x1000c6150` 查表 `0x100396fa0`，**只改写外观相关字段**，其余保持拍摄设置：

| 字段（settings 偏移） | 含义 | 预设值 |
|---|---|---|
| 0x1e0 | 色彩模式 ID | 见上 |
| 0x200 / 0x2b4 / 0x2b8 | 对比度 / 高光 / 阴影（滑块 ±9 → 内部 ±45，步长 5） | 全部外观 0 |
| 0x2bc | 褪色（0..9 → 0..90） | IN 30，SH 60，其余 0 |
| 0x1fc | 饱和度 | 0 |
| 0x208 | 锐度（索引 → −40..50） | PT −10，其余 0 |
| 0x2c4 | 锐度范围（索引 → 20..70） | 50 |
| 0x2c0 | 清晰度（索引 → 0..90） | **VV2 80，PT 0，其余 10** |

FL2/FL3 不在预设表中：只写入 0x1e0，其余字段沿用相机设置（本样张为 0/…/清晰度 10）。

## 4. 渲染管线

任务列表由 Edit 自己的构建函数 `0x1000bfb50`（TileDevForARWFull）按 RAW 和设置生成。本次两台机身得到的实际顺序：

```
TileDiv → RawNR → ITP / Demosaic → [Vatr (DRO)] → GeometricTransform → SSCS
→ LinearMatrix16 → MainGamma → RGB2YCC → AreaComp → ChromaSuppress → Sharpness
→ YGamma → [3DLut] → Spica → YCC2RGB → Marble → [Effect (BW/SE)]
```

每块处理前先运行 **ZcTaskPreprocess**（`0x1000fcf20` → `0x1000e30c0`），它按设置准备渲染对象里的表：伽马、畸变、DRO 网格等。HueSaturation、YNR、ToneCurve、ShadeCorrection 只在用户改了相应设置时才会加入，外观预设下都不启用。

### 4.1 RAW 解码与去马赛克前缩放
- 无损/非压缩 RAW 直接取 DN；cRAW 由 Edit 自己的分段解码（`0x1000a2fd0`，按 `0x7010` 分段，钳位 0x3fff）。
- 预缩放（Demosaic/ITP 内，`0x10015f5xx`）：

  `v = trunc( (raw − black[site]) · WB_int[site] · 0x7311 · 2⁻¹⁹ )`，钳位 ±32767

  `WB_int = trunc( 0x7313 · 2^(曝光补偿/300) · 0x7809/256 )`（`0x100162e40`）。

  两台机身 `0x7311=256`，`0x7809=264`，即白平衡额外 ×1.03125。
- RawNR（CFA 降噪）与 ITP（去马赛克）由 Edit 原生执行。

### 4.2 DRO（ZcTaskVatr）
- 启用条件：settings+0x238 ≠ 0（来自 MakerNote `0xb025`：1–2→模式 1；Auto/Lv→模式 2）。
- Preprocess 用 `0x100114820` 从**整幅 RAW CFA**（ZcARW+0x108 的平面）统计出低分辨率网格（render+0xc01c0），强度在 render+0xc0234。
- Vatr 作用于去马赛克后的 RGB，按像素的绝对坐标定位所在网格单元（`0x100117d40`）并取对应增益。具体的增益公式没有展开，目前以原生执行 Edit 代码为准。
- 这是局部影调处理，所以它和清晰度一样，必须在拿到整幅图的统计之后才能分块计算。

### 4.3 几何校正（ZcTaskGeometricTransformCorrection）
- 参数：`0x7982`（16 点畸变）或 `0x7984`（19 点，存在 `0x7983` 时），`0x7980`（色差 R/B 各一半）。
- 表：`G[i] = 1 + d[i]/32768`；`R[i] = G[i]·(1 + caR[i]·2⁻²¹)`，B 同理。
- 逐像素：`r = |p − c|`，`t = lerp(T, r·f28/rmax)`，`p_src = (p − c)·t·f20 + c`，双线性采样。`f20` 是自动放大系数，用来填满画面（A7C II @70mm 为 0.9583）。
- 镜头**暗角参数不参与渲染**：ShadeCorrection 只在 Edit 自己保存的编辑数据里有设置时才启用。

### 4.4 SSCS
去马赛克后、色彩矩阵前的一步，读取参数集 0xf82 起的字段；原生执行，未单独展开。

### 4.5 LinearMatrix16：逐色相 3×3 矩阵（外观色彩的核心）
- 数据：外观标签 `0x780f`（276 字节），由 `0x1000e1630` 解码出 16 个节点矩阵（色相 bin 0,64,…,960）。再线性插值成 1024 个色相 bin，每条记录为 `[M, I−M]`。已验证 1024 表严格等于节点的线性插值；节点矩阵见 JSON 的 `lm16_per_hue_matrix`。
- 色相：对原图做 5 抽头模糊 `[1,8,14,8,1]/32`（`0x1000afc10`）。在模糊后的 RGB 上计算 `Y=(109R+366G+37B)/512` 与色差，再用八分圆 atan 表（`0x10029e100`）得到 0..1023 的色相。
- 应用（`0x1000b0c00`，对**原图**像素）：

  `out_c = M_c·x + max(0, (N_c·x²)/16384 − T_c)`，`N = I − M`，`T` 本样张为 0，结果钳位 0..16383。
- 新机身（版本 ≥0x3400 且有 `0x780f`）**不使用** `0x7800`。它只在旧机身的 LinearMatrix 路径里用到。

### 4.6 MainGamma
- 表 `T[i]`，i=0..0x7fff：`c = interp(0x7805 → 0x7806, x = 128·i)`，再经“后处理 LUT”（1025 点），最后 `>>2`；负值取 `T[−i] = −T[i]`。
- 后处理 LUT（`0x10013bd00`）：从 37×1025 的曲线族（`0x1002b1310`）中插值选两行，0..470 用 `(对比度−阴影)·0.2+18` 行，471..1024 用 `(对比度+高光)·0.2+18` 行。预设下对比度、高光、阴影均为 0，即第 18 行。

### 4.7 RGB2YCC
- 系数 P（8 个 16 位值）由 `0x100102160` 计算。外观预设下白平衡模式为 1，走插值路径：`0x7842` 加上各白平衡模式表（`0x7843/0x7844/0x7845…`），按 `0x7848` 加权。对 ST 而言结果等于 `0x7841`。每个外观的实际 P 见 JSON 的 `rgb2ycc_P_effective`。
- `k = signed9(P>>2)`（P0..P3），`g = (P>>3)&0xff`（P4..P7）：

  ```
  d1 = R−G, d2 = B−G
  U = d1 + k(d2 符号)/256·d2 ,  V = d2 + k(d1 符号)/256·d1
  C1 = U·0.5·g(U 符号)/64 + 32768 ,  C2 = V·0.5·g(V 符号)/64 + 32768
  Y  = (R·c0 + G·c1 + B·c2) >> 13,  c = 0x7801<<7 = [19,38,7]/64
  ```
- BW 的 P 全为 0，即无色度。

### 4.8 AreaComp / ChromaSuppress / Sharpness / 3DLut / Spica
- 均由 Edit 原生执行，参数来自共享标签与 `srsettings0000.tbl`（Spica 锐化表，由 `0x100119520` 加载）以及 `dcv_psf_dst.bin`（`0x1000f6e50`）。
- 这些任务不带外观专属数据，只受设置里的锐度、锐度范围等字段影响。

### 4.9 YGamma（亮度）
- 拐点 `(0x780c>>5)·64` 以上乘 `0x780d/16384`：ST/NT 为 4096、14848，从 8192 起压缩高光；其余外观为 1024、16384，即不压缩。
- 褪色 f（0..90）：`L = lerp(0x780b, f/10)`，`F = lerp(0x780e, f/10)/16384`，`y = (T[Y] − L)·F + L`。ST/NT 的 `0x780e[0]=17280`，所以 f=0 时亮度 ×1.0547。

### 4.10 YCC2RGB
BT.601 逆变换，14 位输出（`0x100113220`）。

### 4.11 Marble（清晰度）
- 创建条件：清晰度 ≠ 0（或 DRO 模式 1 且参数 0x109c ≠ 0）。
- 流程：先把 RGB 转到工作色空间（与 Effect 相同），再用矩阵 `(0xb44,0xdc3,0x271 / 0x1acc,−0x1ac0,−9 / −0x6ab,−0x964,0x1011)>>11` 转成亮度加两个色差。运行时能看到它在 1/2 和 1/8 分辨率上建立中间图像，最后转回 RGB。
- 实测作用范围约为全分辨率下 ±16 像素（阶跃边缘测试）。强度由清晰度决定（VV2 为 80，多数外观为 10），同时读取参数 `0x794a–0x795e`。

### 4.12 Effect（BW / SE）
- 先转到工作色空间：逐通道 LUT，再乘矩阵 `[[0x13b2,0xca2,−0x54],[0x2ec,0x1abd,0x257],[0x73,0x253,0x1d39]]/8192`，再过 LUT（`0x1000ecbc0`）。处理完用逆变换转回（`0x1000ecdd0`）。
- BW：`R=G=B=(0x991R + 0x12c9G + 0x3a6B)>>13`。
- SE：
  - `Yd = 0.2126R + 0.7152G + 0.0722B`。
  - 权重 w 在暗部（Y601<1344）线性渐入，在高光（>14912）线性渐出。
  - `R = Yd + w·a`，`B = Yd + w·b`，`G = Yd − (0x104c·wa + 0x636·wb)>>13`。
  - `(a,b) = (0x74c5[1]·64, 0x74c5[0]·64) = (896, −960)`。老机型用内置的 (832, −1152)。

### 4.13 输出
14 位 RGB → 8 位：`×255/16383`。

## 5. 复现方式（仓库外的工具脚本）

- `native.py`：把 Edit 的 x86_64 代码映射到原地址 0x100000000，并把外部符号绑定到 glibc/libm。`new`、`malloc` 和 `posix_memalign` 改为清零分配并附带尾部填充；`std::__sort` 由 `shim.c` 提供。
- `npipe.py`：
  - 用 Edit 自己的代码生成参数集、settings、render 对象和任务列表，并执行 Preprocess 与各任务。
  - `run_edit_raw` 从 RAW CFA 开始跑完整条链；几何校正按 4.3 的公式在两段之间完成。
  - `attach_raw` 把整幅 RAW 挂到 ZcARW+0x108，供 DRO 统计使用。
- 边缘处理：DefaultCrop 外的真实传感器像素作为边距，超出传感器的部分用保持 CFA 奇偶的镜像填充。
- 性能：A7M5 全分辨率 12 个外观约 10 分钟。Edit 代码每块约泄漏 450 MB，所以按行分进程运行。

## 6. 验证结果

**ILCE-7M5**（`7849945770.arw`，无损压缩，DRO Auto，拍摄外观 Vivid）：从 RAW 起全程运行 Edit 代码，与 Edit 导出比较：

| 外观 | 16px RMSE | 逐像素 RMSE |
|---|---|---|
| SH | 0.0028 | 0.021 |
| IN / BW | 0.0033 | 0.022–0.025 |
| PT | 0.0036 | 0.018 |
| NT / FL3 | 0.0040 | 0.021–0.023 |
| FL2 | 0.0044 | 0.025 |
| ST | 0.0046 | 0.021 |
| SE | 0.0050 | 0.022 |
| FL | 0.0056 | 0.027 |
| VV | 0.0059 | 0.021 |
| VV2 | 0.0105 | 0.035 |

逐像素误差主要是细节边缘上的 JPEG 与锐化差异；各亮度段无系统偏差。

**ILCE-7CM2**（`2832757259.arw`，cRAW，Edit 导出为 DRO Off）：这次用 LibRaw 解码加 Malvar 去马赛克，替代了 Edit 的 RawNR 和 ITP，从去马赛克之后开始跑 Edit 代码。16px RMSE 为 0.008–0.017，最亮一档偏暗约 0.02。A7M5 从 RAW 全程跑 Edit 代码后没有这个偏差，说明问题出在去马赛克之前的环节。

## 7. 已知限制

- A7C II 这类 cRAW 还没有接入 Edit 自己的 cRAW 解码（`0x1000a2fd0`），用它从 RAW 全程渲染即可消除上面的高光偏差。
- 在 A7M5 上强制 DRO Off（settings+0x218=0，同时保留 Vatr）时 Vatr 会崩溃，尚未排查；按拍摄设置渲染不受影响。
- 图像最外一行、一列与 Edit 相差 5–6 个色阶（边界填充方式与 Edit 不完全一致）。
- SSCS、AreaComp、ChromaSuppress、Sharpness、3DLut、Spica、Marble 的内部算法没有逐条改写成公式，目前通过原生执行 Edit 代码获得精确结果。
